[01] use

one shell script, 165 lines.

jits [-r root] [a|r|u|s|l] [pkg]...
  a  add       install packages and what they need
  r  remove    remove packages
  u  update    sync the repository, upgrade everything
  s  search    search the repository
  l  list      list installed packages

the repository holds one version of every package. there is no dependency resolution because there is nothing to resolve. packages are tarballs compressed with apple's lzfse, four times faster to unpack than gzip. every package has a sha256 in the index and jits checks it before installing. nothing is signed.

jits removes what you tell it to, including what other packages need. it assumes you meant it. configs survive upgrades: the new version lands as file.new, and etcnew merges it.

another repository goes in /etc/jits/repo, or in JITS_REPO for one command. file:// works. which package owns a file:

$ grep -lx bin/oksh /var/db/jits/installed/*/manifest

[02] packaging

a package is a directory in pkgs/ of yagni-linux/repo:

pkgs/yte/version    0.3
pkgs/yte/source     git https://codeberg.org/yagni-linux/yte.git main
pkgs/yte/build      #!/bin/sh -e
                    musl-gcc -std=c99 -Os -s -static -o yte yte.c
                    install -Dm755 yte "$1/bin/yte"
pkgs/yte/depends    what it needs, one per line
pkgs/yte/files/     configs and patches

build installs into $1 as if it were /, by the layout. static, stripped. sources are git <url> <tag>, apt-src <pkg> or apt-deb <pkg>. change a package, bump its version. mkrepo refuses to build a changed package under an old one.

[03] building yagni

$ git clone https://codeberg.org/yagni-linux/repo
$ cd repo
$ ./mkrepo      # every package into repo/
$ ./mkrootfs    # yagni.tar.gz
# ./mkiso       # yagni.iso

this runs on another machine, not on yagni: building the kernel takes gnu make, and gnu does not get in. the build machine needs musl-gcc and lzfse. mkiso needs root, xorriso and mtools. a mirror is repo/ on a web server.
