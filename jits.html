[01] use

jits [-r root] [a|r|u|s|l] [pkg]...
  a  add       install packages and what they need
  r  remove    remove packages
  u  update    sync the repository, upgrade everything
  s  search    search the repository
  l  list      list installed packages

packages are lzfse tarballs, checked against the sha256 in the index. nothing is signed.

jits removes what you tell it to, including what other packages need. configs survive upgrades: the new version lands as file.new, and etcnew merges it.

another repository goes in /etc/jits/repo, or in JITS_REPO for one command, and file:// works. to find the package that owns a file:

$ grep -lx bin/oksh /var/db/jits/installed/*/manifest

[02] packaging

a package is a directory in pkgs/ of yagni-linux/repo:

pkgs/bluesky/version    0.3
pkgs/bluesky/source     git https://codeberg.org/yagni-linux/bluesky.git main
pkgs/bluesky/build      #!/bin/sh -e
                    musl-gcc -std=c99 -Os -s -static -o bluesky bluesky.c
                    install -Dm755 bluesky "$1/bin/bluesky"
pkgs/bluesky/depends    what it needs, one per line
pkgs/bluesky/files/     configs and patches

build installs into $1 as if it were /. everything is static and stripped. sources are git <url> <tag>, apt-src <pkg> or apt-deb <pkg>. when you change a package, bump its version; superlab refuses to rebuild a changed package under the old one.

[03] building yagni

$ git clone https://codeberg.org/yagni-linux/repo
$ cd repo
$ ./superlab      # every package into repo/
$ ./cook htop      # just htop
$ ./mkrootfs    # yagni.tar.gz
# ./mkiso       # yagni.iso

build on another linux machine. the kernel needs gnu make, and gnu doesn't go on yagni. the build machine needs musl-gcc and lzfse. mkiso needs root, xorriso and mtools. any web server serving repo/ is a mirror.
