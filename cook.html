[01] cooking

cook is the package manager. one shell script, 165 lines.

cook [-r root] [a|r|u|s|l] [pkg]...
  a  add       install packages and what they need
  r  remove    remove packages
  u  update    sync the repository, upgrade everything
  s  search    search the repository
  l  list      list installed packages

tahiti, the repository, holds exactly one version of every package, so cook never has to choose. packages are tarballs compressed with apple's lzfse, and every one is checked against its sha256 in the index before it goes in. nothing is signed.

cook removes whatever you tell it to, even things other packages need. it figures you meant it. configs you edited survive upgrades: the new one shows up as file.new and etcnew merges it.

point it at another repository with /etc/cook/repo, or COOK_REPO for one command. file:// works. which package owns a file:

$ grep -lx bin/oksh /var/db/cook/installed/*/manifest

[02] recipes

a package is a directory in pkgs/ of redemption-linux/repo:

pkgs/bluesky/version    0.3
pkgs/bluesky/source     git https://codeberg.org/redemption-linux/bluesky.git main
pkgs/bluesky/build      #!/bin/sh -e
                        musl-gcc -std=c99 -Os -s -static -o bluesky bluesky.c
                        install -Dm755 bluesky "$1/bin/bluesky"
pkgs/bluesky/depends    what it needs, one per line
pkgs/bluesky/files/     configs and patches

build installs into $1 as if it were /, following the layout. static and stripped. sources are git <url> <tag>, apt-src <pkg> or apt-deb <pkg>. change a recipe and bump its version, or the superlab will not touch it.

[03] the superlab

$ git clone https://codeberg.org/redemption-linux/repo
$ cd repo
$ ./superlab    # cooks every package into repo/
$ ./mkrootfs    # redemption.tar.gz
# ./mkiso       # redemption.iso

the lab runs on another machine. the kernel wants gnu make, and gnu is not welcome on redemption. the build box needs musl-gcc and lzfse, and mkiso also needs root, xorriso and mtools. a mirror is just repo/ on a web server.
