-> the plan

the job, start to finish. no installer and no wizard, just you, a shell and a stick.

1. get in

write redemption.iso to a usb stick, turn secure boot off and boot it. you wake up as root. everything the job needs is on the stick, so leave the network out of it.

# dd if=redemption.iso of=/dev/sdX bs=4M

2. stake the claim

the kernel only knows root by its gpt partition name. call it redemption or it rides right past.

# sfdisk /dev/sda <<EOF
label: gpt
size=256M, type=uefi, name=BOOT
type=linux, name=redemption
EOF
# mkfs.vfat -F 32 -n BOOT /dev/sda1
# mkfs.ext4 -L redemption /dev/sda2
# mount /dev/sda2 /mnt
# mkdir /mnt/boot
# mount /dev/sda1 /mnt/boot

3. move in

check the haul, unpack it, set a root password. tar grumbles about permissions on /boot because it is fat. let it grumble.

# cd /media/install
# sha256sum -c redemption.tar.gz.sha256
# tar xzf redemption.tar.gz -C /mnt
# chroot /mnt passwd

4. bring the wifi

only got wifi on this machine? take it with you now, from the stick. more in wifi.

# COOK_REPO=file:///media/install/repo cook -r /mnt a wpa_supplicant firmware-iwlwifi yutils

5. ride out

# umount /mnt/boot /mnt
# reboot

when the job goes wrong

stuck at Waiting for root device PARTLABEL=redemption: you named the partition wrong. sfdisk --part-label /dev/sda 2 redemption fixes it.

some firmware will not boot the fallback path off an internal disk. give it a boot entry with efibootmgr from another live system.

dual booting: mount the efi partition you already have at /mnt/boot, and move any EFI/BOOT/BOOTX64.EFI out of the way first. redemption puts its kernel right there.
