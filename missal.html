[1] INTROIT, THE PACKAGE MANAGER

introit (just install that shit) is a single POSIX shell script, living in requiem-linux/introit and installed into /bin of every requiem system as part of base.

It handles downloads, checksums, dependencies, configuration files and apps. It does not build anything: packages are built by mkrepo (see Building the system) and introit installs the result.

To see a list of supported commands, execute introit without arguments.

introit [-r root] a|r|u|s|l [pkg]...
  a  add a package and what it depends on
  r  remove a package
  u  sync the index, upgrade everything that changed
  s  search the index
  l  list installed packages and apps

-r /mnt does the same to a system mounted at /mnt. mkrootfs and mkiso use it to build their systems.

All downloads of one a run at the same time. introit uses curl, or wget if curl is not installed. file:// repositories are copied with cp.

Every download is checked against the sha256 in the index before anything is unpacked. A package containing an absolute path, a .. or a path through a symlink is refused. Packages are not signed: whoever controls the repository controls your packages.

Installed files are moved into place from /var/db/introit/stage. Files that the new version no longer ships are removed. A file under /etc that you edited is not overwritten; the new copy is written next to it as file.new.

To completely remove a package:

$ doas introit r htop

introit removes every file listed in the package's manifest and prunes empty directories. If another package depends on it, introit says so and removes it anyway.

INTROIT_REPO=file:///media/install/repo

Overrides /etc/introit/repo for one command.

INTROIT_APPS=$HOME/apps

Where apps are installed. Defaults to ~/apps, or /apps when running as root.

[2] /VAR/DB/INTROIT

/var/db/introit is where introit keeps everything it knows.

/var/db/introit/repo/index          # the index, fetched by introit u
/var/db/introit/installed/<name>/   # one directory per installed package
    version                         # the installed version
    depends                         # its dependencies, one per line
    manifest                        # every file it installed
    etcsums                         # sha256 of its files in /etc, as shipped
/var/db/introit/cache               # downloads. Safe to empty
/var/db/introit/stage               # unpacking. Safe to empty

Erasing a package's manifest will break introit r for that package, and the next upgrade will leave its old files behind. Erasing etcsums makes introit treat every file of that package in /etc as edited.

Apps are not recorded here. An app's directory in ~/apps or /apps is its entire record.

A user without write access to /var/db/introit gets the index and the download cache in ~/.cache/introit instead.

To find which package owns a file:

$ grep -lx bin/oksh /var/db/introit/installed/*/manifest

[3] WRITING PACKAGES

A package is a directory in pkgs/ of the repo. It contains up to five files.

pkgs/<name>/version
pkgs/<name>/source
pkgs/<name>/depends
pkgs/<name>/build
pkgs/<name>/app

version and build are required. version is copied into the index as is, so it can be anything; the convention is the upstream version, then -1, -2 for rebuilds.

git <url> <tag>
apt-src <package>
apt-deb <package>...

source says where the code comes from: a shallow clone of a git tag or branch, an Ubuntu source package, or Ubuntu binary packages, which are only used for firmware, fonts and certificates. It is fetched once into src/<name>. Without a source, the package's own directory is the source.

depends lists the packages it needs at runtime, one per line.

build is a shell script. It runs inside the source directory and installs into $1 as if $1 were /. $PKG is the package's directory, for patches and configuration files. $ROOT is the top of the repo. Compile with musl-cc, which links static whether you ask or not.

After build, mkrepo moves anything in usr/bin, usr/sbin or sbin to bin, and usr/share to share. Anything still in usr, lib, lib64 or libexec fails the build.

app is an empty file. Its presence turns the package into an app (see Apps): mkrepo packs it as one directory with a version file inside, and marks it in the index.

Increase the version whenever you change anything in a package's directory. mkrepo refuses to rebuild a changed package under its old version, since nobody who has it installed would get the change.

[4] BUILDING THE SYSTEM

$ git clone https://codeberg.org/requiem-linux/repo
$ cd repo
$ ./mkrepo        # every package that isn't built yet, into repo/
$ ./mkpkg htop    # just htop
$ ./mkrootfs      # requiem.tar.gz, the base system
# ./mkiso         # requiem.iso

The build host needs clang, lld, compiler-rt, lzfse and GNU make. Make is only there because the kernel's build system wants it; nothing GNU ends up in a package.

cc/ holds musl-cc, which runs clang against a musl that cc/mksysroot builds with clang into cc/sysroot on the first run. mkrepo puts cc/ first in PATH. cc/gcc is a stub that fails the build, so a package that calls gcc behind your back is caught.

SUMS=1 ./mkrepo

Writes sha256 sums into the index. Without it the index carries - and introit skips the check. Ship with it.

Put repo/ on any web server and point /etc/introit/repo at it. mkiso needs root, xorriso and mtools.

[5] INSTALLING THE SYSTEM

Write requiem.iso to a USB stick and boot it with secure boot disabled. It boots into a root shell. /media/install has the base tarball and an offline repository for wifi.

# dd if=requiem.iso of=/dev/sdX bs=4M

The kernel's command line contains root=PARTLABEL=requiem, so the root partition has to carry that GPT name. The EFI partition holds the kernel.

# sfdisk /dev/sda <<EOF
label: gpt
size=256M, type=uefi, name=BOOT
type=linux, name=requiem
EOF
# mkfs.vfat -F 32 -n BOOT /dev/sda1
# mkfs.ext4 -L requiem /dev/sda2
# mount /dev/sda2 /mnt
# mkdir /mnt/boot
# mount /dev/sda1 /mnt/boot
# cd /media/install
# sha256sum -c requiem.tar.gz.sha256
# tar xzf requiem.tar.gz -C /mnt
# chroot /mnt passwd

tar warns about permissions on /boot. FAT has none; the warnings are harmless.

For wifi, install it from the stick before rebooting (see Using a WLAN):

# INTROIT_REPO=file:///media/install/repo introit -r /mnt a wpa_supplicant firmware-iwlwifi yutils
# umount /mnt/boot /mnt
# reboot

If boot stops at Waiting for root device PARTLABEL=requiem, the partition is misnamed: sfdisk --part-label /dev/sda 2 requiem.

Some firmware will not boot the fallback path EFI/BOOT/BOOTX64.EFI from an internal disk. Add an entry from another live system:

# efibootmgr -c -d /dev/sda -p 1 -L requiem -l '\EFI\BOOT\BOOTX64.EFI'

To dual boot, mount the existing EFI partition at /mnt/boot instead of creating one. Move an existing EFI/BOOT/BOOTX64.EFI out of the way first.

[6] UPDATING THE SYSTEM

$ doas introit u

Fetches the index and upgrades every installed package and app whose version in the index differs from the installed one. Different, not newer: a version that goes down is installed too.

Files in /etc that you changed are kept, and the new version is written as file.new. etcnew, from yutils, lists them and merges them:

$ etcnew                 # list
$ etcnew diff /etc/profile
$ etcnew take /etc/profile
$ etcnew keep /etc/profile

[7] SYSTEM ADMINISTRATION

requiem is built differently from most distributions, and some of what you know does not apply.

[7.1] THE FILE SYSTEM

requiem does not follow the Filesystem Hierarchy Standard.

Every program is statically linked against musl. There is no dynamic loader and no /lib. A binary linked against glibc will not run.

For legacy support, /usr is a symlink to /, so #!/usr/bin/env works. There is no /sbin; root and users run the same programs from /bin.

/bin        # every program
/share      # data, fonts, firmware, kernel modules, headers, static libraries
/etc        # configuration
/boot       # the EFI partition. holds the kernel and nothing else
/var        # logs and /var/db/introit
/apps       # apps installed by root
/home       # users, and their ~/apps
/root
/mnt
/dev /proc /sys /run /tmp   # created at boot
/usr        # symlink to /

musl-dev puts the headers in /share/include and the static libraries in /share/lib.

[7.2] APPS

An app is a package that is installed as one directory. Install one with introit as a regular user and it goes in ~/apps. Install it as root and it goes in /apps, for every user. A regular user needs no root for this.

$ introit a netsurf
$ ls ~/apps/netsurf
bin  share  version

/etc/profile adds every ~/apps/*/bin and /apps/*/bin to PATH at login. Move a directory out of ~/apps and the app is not installed anymore. Move it back and it is. The change shows up in the next shell.

An app finds its own files relative to where it is, so the directory can be renamed or moved between ~/apps and /apps.

Installing an app whose dependencies from the base system are missing fails, and prints the command to install them as root.

The apps in the repository are netsurf and havoc. Command line programs are ordinary packages in /bin.

[7.3] THE INIT SYSTEM

The firmware runs /boot/EFI/BOOT/BOOTX64.EFI, which is the kernel. There is no bootloader and no initramfs. The kernel's command line is built in:

root=PARTLABEL=requiem rootwait rw init=/bin/init firmware_class.path=/share/firmware

requiem uses busybox init. It reads /etc/inittab, runs /etc/init.d/rcS, and starts a getty on tty1 and on the serial port. There are no runlevels and no services.

rcS is the whole boot. It mounts the virtual filesystems and /etc/fstab, sets the hostname, loads a module for every device the kernel reports, starts mdev, starts wpa_supplicant if /etc/wpa_supplicant.conf exists, and runs udhcpc on every network interface. To start something at boot, add a line to it.

/etc/init.d/rcS       # boot
/etc/inittab          # consoles
/etc/fstab            # mounts
/etc/hostname         # hostname
/etc/doas.conf        # root access. permits the wheel group
/etc/introit/repo     # the repository
/etc/profile          # PATH, the prompt

[7.4] LOGGING

There is no syslog. Kernel messages are kept out of the console by dmesg -n 1 in rcS; read them with dmesg.

[8] THE DESKTOP

kyrie is the Wayland compositor of requiem. It runs on swc. The terminal is havoc, the launcher dmenu and the browser netsurf.

# introit a kyrie netsurf wallpaper
$ startw

startw starts kyrie on the current virtual terminal. Before that it reads ~/.config/kyrie/env, so variables set there reach kyrie and every program started from it.

KYRIE_BORDER=6         # border width in pixels
KYRIE_FOCUS=c9c9c6     # border colour of the focused window
KYRIE_UNFOCUS=494949   # border colour of the others
TERMINAL=havoc         # super + return
MENU=dmenu_run         # super + d
BROWSER=netsurf        # super + w, from the default keys script

super + a letter that kyrie does not use itself runs ~/.config/kyrie/keys with that letter, or S- and the letter with shift. Without one, /share/kyrie/keys is used; copy it to start from. KYRIE_KEYS points somewhere else.

case $1 in
w) exec netsurf ;;
S-x) exec havoc tract ;;
esac

The built-in keys are listed on the kyrie page.

[9] OTHER ADVICE

Adding a user

  • Execute introit a yutils.
  • Execute mkuser foo. foo gets oksh as shell and the groups wheel, video, input and audio.
  • wheel may use doas.

Using a WLAN

  • Install wpa_supplicant, yutils, and firmware-iwlwifi for Intel or firmware-realtek for Realtek cards. cat /sys/bus/pci/devices/*/vendor shows 0x8086 for Intel and 0x10ec for Realtek.
  • Execute wifi network password. It writes /etc/wpa_supplicant.conf and connects. rcS connects again at every boot.
  • WPA2 only. WPA3 and enterprise networks do not work.

Getting a DHCP address

  • rcS runs udhcpc on every interface at boot. USB tethering and USB Ethernet work if they are plugged in before boot.

Sound

  • Install alsa-utils. Sound starts muted.
  • Execute vol 80.

Wallpaper

  • Execute setwall /share/wallpapers/tower.png, or setwall '#1a4270' for a colour.
  • setwall with no argument puts the saved one back. startw runs it.

Screenshots

  • Press super + p, or execute shot file.png.

Writing scripts

  • The boot and the system scripts run on busybox ash. Write for POSIX sh.

Keyboard layouts

  • Only the US layout is included.
