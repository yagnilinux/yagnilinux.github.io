[1] REQUIEM DOES THINGS A BIT DIFFERENTLY

requiem does not follow the FHS.

everything is statically linked against musl. there is no dynamic loader, so there is no /lib. a program built against glibc will not run here. build it static, or package it.

/usr is a symlink to /, kept so #!/usr/bin/env works. there is no /sbin. root and users run the same programs.

everything is built with clang, lld and compiler-rt. no binary contains gcc or libgcc. see lix.

/bin -> programs

/share -> data, fonts, firmware, kernel modules, headers and static libraries

/etc -> configuration

/boot -> the efi partition, holding the kernel

/var -> logs, and the package database in /var/db/introit

/apps -> apps for every user

/home, /root -> users, and their ~/apps

/mnt -> other filesystems

/dev, /proc, /sys, /run, /tmp -> made at boot

/usr -> a symlink to /

[1.1] APPS

an app is one folder. introit puts it in ~/apps, or in /apps when you are root. no root needed for your own.

$ introit a netsurf
$ ls ~/apps/netsurf
bin  share  version

your shell picks up ~/apps/*/bin and /apps/*/bin when it starts. move a folder out of ~/apps and the app is uninstalled. move it back and it's installed again. delete it and there is nothing left to clean up. a new app shows up in a new shell.

everything below ~/apps is yours, use it wisely.

netsurf and havoc are apps. command line tools are not, they live in /bin. if an app needs something from the base system that isn't installed, introit tells you what to run as root first.

[2] INSTALLING

there is no installer. you partition a disk, unpack a tarball and set a password. if you've installed arch, you've done harder.

1. boot the iso. write requiem.iso to a usb stick and boot it with secure boot off. it starts a root shell. everything the install needs is on the stick, so you don't need a network.

# dd if=requiem.iso of=/dev/sdX bs=4M

2. partition. the kernel mounts the partition named requiem as root, so use exactly these names.

# sfdisk /dev/sda <<EOF
label: gpt
size=256M, type=uefi, name=BOOT
type=linux, name=requiem
EOF

3. filesystems.

# mkfs.vfat -F 32 -n BOOT /dev/sda1
# mkfs.ext4 -L requiem /dev/sda2
# mount /dev/sda2 /mnt
# mkdir /mnt/boot
# mount /dev/sda1 /mnt/boot

4. the base system. tar warns about permissions on /boot. it's fat, ignore it.

# cd /media/install
# sha256sum -c requiem.tar.gz.sha256
# tar xzf requiem.tar.gz -C /mnt

5. root password.

# chroot /mnt passwd

6. wifi, if you need it. skip this on ethernet. realtek cards want firmware-realtek instead.

# INTROIT_REPO=file:///media/install/repo introit -r /mnt a wpa_supplicant firmware-iwlwifi yutils

7. reboot.

# umount /mnt/boot /mnt
# reboot

it didn't boot. stuck at Waiting for root device PARTLABEL=requiem? the second partition has the wrong name:

# sfdisk --part-label /dev/sda 2 requiem

some firmware won't boot the fallback path off an internal disk. give it an entry from another live system:

# efibootmgr -c -d /dev/sda -p 1 -L requiem -l '\EFI\BOOT\BOOTX64.EFI'

dual booting. mount the efi partition you already have at /mnt/boot instead of making one. if EFI/BOOT/BOOTX64.EFI is already there, move it out of the way first and give requiem its own entry with efibootmgr.

[3] BOOTING

the firmware runs /boot/EFI/BOOT/BOOTX64.EFI. that file is the kernel, with its command line built in:

root=PARTLABEL=requiem rootwait rw init=/bin/init firmware_class.path=/share/firmware

busybox init reads /etc/inittab and runs /etc/init.d/rcS. rcS is the whole boot: it mounts the filesystems, loads a module for every device the kernel finds, starts mdev, starts wifi if it's set up and asks for an address on every network card. to start something at boot, add a line to it.

boot -> /etc/init.d/rcS

consoles -> /etc/inittab

mounts -> /etc/fstab

hostname -> /etc/hostname

root access -> /etc/doas.conf

repository -> /etc/introit/repo

prompt -> /etc/profile

[4] USERS

log in as root and add a user.

# introit a yutils
# mkuser foo

foo gets oksh, the openbsd korn shell, and the wheel group. wheel can use doas.

$ doas introit u

scripts and the boot run on busybox ash. write them for ash.

[5] WIFI

intel (iwlwifi) -> firmware-iwlwifi

realtek (rtw88, rtw89) -> firmware-realtek

don't know your card? cat /sys/bus/pci/devices/*/vendor. 0x8086 is intel, 0x10ec is realtek. other cards need their firmware packaged.

# introit a wpa_supplicant firmware-iwlwifi yutils
# wifi "network" "password"

it connects now, and at every boot after. networkmanager needs a daemon and dbus to do the same.

wpa2 only. wpa3 and enterprise networks don't work. usb tethering and usb ethernet work if they're plugged in before boot. none of the firmware has been tested on a real card yet.

[6] THE DESKTOP

kyrie is the wayland compositor of requiem. havoc is the terminal, dmenu the launcher and netsurf the browser.

# introit a kyrie netsurf wallpaper
$ startw

super + return opens havoc, super + d opens dmenu. the other keys are on the kyrie page.

wallpaper. no argument puts the saved one back.

$ setwall /share/wallpapers/tower.png
$ setwall '#1a4270'

screenshots. super + p, or:

$ shot shot.png

ricing. ~/.config/kyrie/env is read at startup:

KYRIE_BORDER=6
KYRIE_FOCUS=c9c9c6
KYRIE_UNFOCUS=494949
TERMINAL="havoc"
MENU="dmenu_run"

~/.config/kyrie/keys is a shell script. super + x runs it with x, super + shift + x with S-x:

case $1 in
w) exec netsurf ;;
S-x) exec havoc tract ;;
esac

sound starts muted. vol 80 fixes that. yt plays a video's audio.

missing: keyboard layouts other than us, and a video player.

[7] INTROIT

introit (just install that shit) is the package manager of requiem. it is one posix sh script. one version of every package, so no dependency hell.

introit [-r root] [a|r|u|s|l] [pkg]...
  a  add       install a package and what it needs
  r  remove    remove a package
  u  update    sync the repository, upgrade everything
  s  search    search the repository
  l  list      list installed packages

-r /mnt does the same to a system mounted somewhere else.

  • one command installs a package and everything it needs.
  • every download is checked against the sha256 in the index.
  • your configs survive upgrades. the new one lands as file.new, etcnew merges it.
  • remove anything. you're an adult.

packages are not signed. whoever controls the repository controls your packages, same as a git clone.

another repository. put the address in /etc/introit/repo, or set INTROIT_REPO for one command. file:// works.

which package owns a file.

$ grep -lx bin/oksh /var/db/introit/installed/*/manifest

[8] WRITING PACKAGES

packaging is easy. make a directory in pkgs/ and fill in up to four files. if you've written a kiss package, you already know how.

pkgs/<name>/version     the version
pkgs/<name>/depends     what it needs, one per line
pkgs/<name>/source      where to get it
pkgs/<name>/build       how to build it
pkgs/<name>/app         empty. makes it an app

build is a shell script that installs the program into $1, as if $1 were /. $PKG is your package's directory, for configs and patches. musl-cc always links static. anything left in /usr, /lib or /sbin fails the build.

git <url> <tag>     a git repository
apt-src <pkg>       an ubuntu source package
apt-deb <pkg>...    ubuntu binary packages, firmware only

bump the version whenever you change a package, or nobody gets the change. mkrepo won't let you forget.

put repo/ on any web server and point /etc/introit/repo at it. that's a distribution.

[9] BUILDING REQUIEM

the whole distribution is in requiem-linux/repo.

$ git clone https://codeberg.org/requiem-linux/repo
$ cd repo
$ ./mkrepo        # every package
$ ./mkpkg htop    # just htop
$ ./mkrootfs      # requiem.tar.gz
# ./mkiso         # requiem.iso

build on another linux machine with clang, lld, compiler-rt and lzfse. the kernel also wants gnu make, which requiem doesn't ship. cc/gcc is a stub that fails the build, so gcc can't sneak in. mkiso needs root, xorriso and mtools.

rules.

  • shell is posix sh.
  • programs are static against musl.
  • a package that needs a library builds it itself.
  • base is what a machine needs to boot and install packages. everything else is a package.

testing. install the tarball on a fresh disk in qemu, install every package, log in as a normal user and start the desktop. if that works, send it.

sending changes. pull request against requiem-linux/repo. bump the version of every package you touch. if your patch adds a dependency, the commit message says why.
