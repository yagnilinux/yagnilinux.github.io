[1] INTROIT, THE PACKAGE MANAGER

introit is a POSIX shell script of 177 lines, installed into /bin as part of sys/base. Its source is requiem-linux/introit.

introit installs, upgrades and removes binary packages. It does not build them; that is done by mkrepo, described in Building the system.

introit [-r root] a|r|u|s|l [pkg]...
  a  add a package and what it depends on
  r  remove a package
  u  sync the index, upgrade everything that changed
  s  search the index
  l  list installed packages and apps

Packages are named by category and name, for example browsers/netsurf. The name alone is enough as long as no other category has a package of that name.

With -r /mnt, introit works on the system mounted at /mnt instead of the running one. mkrootfs and mkiso use it this way.

The downloads of one command run in parallel, using curl, or wget if curl is not installed. A file:// repository is read with cp. Each download is checked against the sha256 in the index before it is unpacked. Packages are not signed, so whoever controls the repository controls what gets installed.

A package is unpacked into /var/db/introit/stage and its files are then moved into place. Files that the new version no longer contains are removed. A file in /etc that has been edited is left alone, and the new version is written next to it as file.new.

$ doas introit r utils/pfetch

This removes every file in the package's manifest, along with any directories left empty. introit does not check whether another package depends on the one being removed.

INTROIT_REPO=file:///media/install/repo

Overrides /etc/introit/repo for one command.

INTROIT_APPS=$HOME/apps

Sets where apps are installed. The default is ~/apps, or /apps for root.

[2] /VAR/DB/INTROIT

introit keeps its state in /var/db/introit.

/var/db/introit/repo/index                    # the index, fetched by introit u
/var/db/introit/installed/<category>/<name>/  # one directory per installed package
    version                                   # the installed version
    depends                                   # its dependencies, one per line
    manifest                                  # every file it installed
    etcsums                                   # sha256 of its files in /etc, as shipped
/var/db/introit/cache                         # downloads. Safe to empty
/var/db/introit/stage                         # unpacking. Safe to empty

Without a package's manifest, introit cannot remove the package, and an upgrade will leave its old files behind. Without its etcsums, every file of the package in /etc counts as edited.

Apps are not recorded here. The directory of an app is its only record.

A user who cannot write to /var/db/introit has the index and the download cache in ~/.cache/introit instead.

To find the package that owns a file:

$ grep -lx bin/oksh /var/db/introit/installed/*/*/manifest

[3] WRITING PACKAGES

A package is a directory in pkgs/<category>/ of the repo, containing up to five files.

version -> Required. Copied into the index as it is. By convention, the upstream version followed by -1, -2 and so on for rebuilds.

build -> Required. A shell script that installs the program into $1.

source -> Where the code comes from. Without it, the package's own directory is the source.

depends -> The packages it needs at runtime, one per line, with their category.

app -> An empty file that makes the package an app.

git <url> <tag>
apt-src <package>
apt-deb <package>...

A source is a shallow clone of a git tag or branch, an Ubuntu source package, or Ubuntu binary packages. Binary packages are only used for firmware, fonts and certificates. The source is fetched once into src/<name>.

build runs inside the source directory and installs into $1 as if $1 were /. $PKG is the package's directory, for patches and configuration files, and $ROOT is the top of the repo. Programs are compiled with musl-cc, which always links statically.

After build, mkrepo moves usr/bin, usr/sbin and sbin to bin, and usr/share to share. A package that still has files in usr, lib, lib64 or libexec fails to build.

An app is packed as a single directory with a version file inside, and is marked as an app in the index.

The version has to change whenever anything in the package's directory changes. Otherwise nobody who has the package installed would receive the change, and mkrepo refuses to build it.

[4] BUILDING THE SYSTEM

$ git clone https://codeberg.org/requiem-linux/repo
$ cd repo
$ ./mkrepo        # every package that is not built yet, into repo/
$ ./mkpkg tract   # only tract
$ ./mkrootfs      # requiem.tar.gz, the base system
# ./mkiso         # requiem.iso

The build machine needs clang, lld, compiler-rt, lzfse and GNU make. Make is needed only because the kernel's build system depends on it; nothing from GNU ends up in a package.

cc/musl-cc runs clang against a musl that cc/mksysroot builds with clang into cc/sysroot on the first run. mkrepo puts cc/ first in PATH. cc/gcc is a stub that fails the build, so a package that tries to call gcc is caught.

SUMS=1 ./mkrepo

Writes sha256 sums into the index. Without it, the index has - in their place and introit skips the check.

Packages are written to repo/ as <category>.<name>@<version>.tar.lzfse. Any web server that serves repo/ is a mirror. mkiso needs root, xorriso and mtools.

[5] INSTALLING THE SYSTEM

Write requiem.iso to a USB stick and boot from it with secure boot disabled. It starts a root shell. /media/install holds the base tarball and a small repository with what is needed for wifi.

# dd if=requiem.iso of=/dev/sdX bs=4M

The kernel mounts the partition with the GPT name requiem as root, so the root partition has to be given that name. The kernel itself goes on the EFI partition.

# sfdisk /dev/sda <<EOF
label: gpt
size=256M, type=uefi, name=BOOT
type=linux, name=requiem
EOF
# mkfs.vfat -F 32 -n BOOT /dev/sda1
# mkfs.ext4 -L requiem /dev/sda2
# mount /dev/sda2 /mnt
# mkdir /mnt/boot
# mount /dev/sda1 /mnt/boot
# cd /media/install
# sha256sum -c requiem.tar.gz.sha256
# tar xzf requiem.tar.gz -C /mnt
# chroot /mnt passwd

tar prints warnings about permissions on /boot. FAT has no permissions, and the warnings can be ignored.

For wifi, install the packages from the stick before rebooting (see Using a WLAN):

# INTROIT_REPO=file:///media/install/repo introit -r /mnt a net/wpa_supplicant firmware/iwlwifi sys/qoltils
# umount /mnt/boot /mnt
# reboot

If the boot stops at Waiting for root device PARTLABEL=requiem, the root partition has the wrong name. Rename it with sfdisk --part-label /dev/sda 2 requiem.

Some firmware will not boot EFI/BOOT/BOOTX64.EFI from an internal disk. In that case, add a boot entry from another live system:

# efibootmgr -c -d /dev/sda -p 1 -L requiem -l '\EFI\BOOT\BOOTX64.EFI'

To dual boot, mount the existing EFI partition at /mnt/boot instead of creating a new one. If it already contains EFI/BOOT/BOOTX64.EFI, move that file elsewhere first.

[6] UPDATING THE SYSTEM

$ doas introit u

This fetches the index and upgrades every installed package and app whose version in the index differs from the installed one. A lower version is installed as well.

Edited files in /etc are kept, and the new versions are written as file.new. etcnew, from sys/qoltils, lists and merges them:

$ etcnew
$ etcnew diff /etc/profile
$ etcnew take /etc/profile
$ etcnew keep /etc/profile

[7] SYSTEM ADMINISTRATION

requiem is put together differently from most distributions, and some habits from them do not apply here.

[7.1] THE FILE SYSTEM

Every program is statically linked against musl. There is no dynamic loader and no /lib, and a program linked against glibc will not run.

/usr is a symlink to /, kept so that #!/usr/bin/env works. There is no /sbin; root and users run the same programs from /bin.

/bin        # programs
/share      # data, fonts, firmware, kernel modules, headers and static libraries
/etc        # configuration
/boot       # the EFI partition, with the kernel
/var        # logs and /var/db/introit
/apps       # apps installed by root
/home       # users, and their ~/apps
/root
/mnt
/dev /proc /sys /run /tmp   # created at boot
/usr        # symlink to /

sys/musl-dev installs the headers into /share/include and the static libraries into /share/lib.

[7.2] APPS

An app is a package that is installed as one directory. A user who installs an app with introit gets it in ~/apps, without needing root. When root installs it, it goes in /apps and every user has it.

$ introit a browsers/netsurf
$ ls ~/apps/netsurf
bin  share  version

/etc/profile adds every ~/apps/*/bin and /apps/*/bin to PATH at login. An app that is moved out of ~/apps is no longer installed, and one that is moved back is installed again, from the next login on.

An app finds its own files relative to its directory, so the directory can be moved between ~/apps and /apps.

If an app needs packages from the base system that are not installed, the install fails and prints the command to install them as root.

The apps in the repository are browsers/netsurf and terminals/havoc. Command line programs are ordinary packages in /bin.

[7.3] LIBERA, THE BOOT

libera is the name for how requiem boots. There is no bootloader and no initramfs. The firmware runs /boot/EFI/BOOT/BOOTX64.EFI, which is the kernel, with its command line built in:

root=PARTLABEL=requiem rootwait rw init=/bin/init firmware_class.path=/share/firmware

busybox init runs /etc/libera, then starts a getty on tty1 and on the serial port, as listed in /etc/inittab. There are no runlevels and no services.

/etc/libera is the whole boot. It mounts the virtual filesystems and /etc/fstab, sets the hostname, loads a module for every device the kernel reports, starts mdev, starts wpa_supplicant if /etc/wpa_supplicant.conf exists, and runs udhcpc on every network interface. Anything else that should start at boot can be added to it.

/etc/libera -> the boot

/etc/inittab -> consoles

/etc/fstab -> mounts

/etc/hostname -> hostname

/etc/doas.conf -> root access, for the wheel group

/etc/introit/repo -> the repository

/etc/profile -> PATH and the prompt

[7.4] LOGGING

There is no syslog. libera runs dmesg -n 1 to keep kernel messages off the console; they can be read with dmesg.

[8] THE DESKTOP

kyrie is the Wayland compositor of requiem. It is built on swc. The terminal is havoc, the launcher is dmenu and the browser is netsurf.

# introit a desktop/kyrie browsers/netsurf desktop/wallpaper
$ startw

startw starts kyrie on the current virtual terminal. It reads ~/.config/kyrie/env first, so variables set there apply to kyrie and to every program started from it.

KYRIE_BORDER=6         # border width in pixels
KYRIE_FOCUS=c9c9c6     # border colour of the focused window
KYRIE_UNFOCUS=494949   # border colour of the other windows
TERMINAL=havoc         # super + return
MENU=dmenu_run         # super + d
BROWSER=netsurf        # super + w

Super and any letter kyrie does not use itself runs ~/.config/kyrie/keys with that letter, or with S- and the letter when shift is held. If that file does not exist, /share/kyrie/keys is used, which is also a good starting point. KYRIE_KEYS points to another file.

case $1 in
w) exec netsurf ;;
S-x) exec havoc tract ;;
esac

The built-in keys are listed on the kyrie page.

[9] OTHER ADVICE

Adding a user

  • Install sys/qoltils.
  • Run mkuser foo. The user gets oksh as shell and the groups wheel, video, input and audio. Members of wheel can use doas.

Using a WLAN

  • Install net/wpa_supplicant, sys/qoltils, and firmware/iwlwifi for Intel or firmware/realtek for Realtek cards. cat /sys/bus/pci/devices/*/vendor prints 0x8086 for Intel and 0x10ec for Realtek.
  • Run wifi network password. This writes /etc/wpa_supplicant.conf and connects. libera connects again at every boot.
  • Only WPA2 is supported. WPA3 and enterprise networks do not work.

Getting a DHCP address

  • libera runs udhcpc on every network interface at boot. USB tethering and USB Ethernet work if they are plugged in before booting.

Sound

  • Install sound/alsa-utils. Sound is muted at first.
  • Run vol 80.

Wallpaper

  • Run setwall /share/wallpapers/tower.png, or setwall '#1a4270' for a plain colour.

Screenshots

  • Press super + p, or run shot file.png.

Writing scripts

  • libera and the system scripts run on busybox ash. Scripts should be POSIX sh.

Keyboard layouts

  • Only the US layout is included.
