-> goals

“Perfection is achieved not when there is nothing more to add, but when there is nothing left to take away.”

a goal that can be quoted to excuse a bad decision was written badly. these are meant to be hard to misuse.

  • users know what they are doing.
  • users take part. package what's missing and send it back.
  • the whole system stays small enough for one person to read.
  • base is what a machine needs to boot and install packages. nothing else.
  • a script you can read beats a daemon you have to trust.
  • things get broken when keeping them means keeping complexity.

what we expect from you

every user of redemption is a developer of redemption, whether they meant to be or not. we expect the following, and if you skip it, you will be sent back here.

  • you read the docs before asking anything.
  • you read the script before you blame it. cook is 165 lines and the boot is 32.
  • when something is missing, you package it and send it back. a request for someone else to package it is not a contribution.
  • a bug report comes with the command you ran and everything it printed.
  • you already know your way around a shell, a partition table and a kernel log. we will not teach you.
  • when someone helping you asks for something, you give exactly that.
