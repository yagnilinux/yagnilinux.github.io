goals

  • The user knows what they are doing.
  • Users take part. What is missing gets packaged by whoever needs it, and sent back.
  • The whole system stays small enough for one person to read.
  • The base system contains what a machine needs to boot and install packages, and nothing more.
  • A script that can be read is preferred to a daemon that has to be trusted.
  • Compatibility is dropped when keeping it would mean keeping complexity.

expectations

blackout stays small because the people who use it help build it. Before installing it, you should know the following.

  • It is installed and set up by hand. You will partition a disk, edit files in /etc and read shell scripts.
  • The documentation is short, and so is the code. Most answers are in one of them.
  • The repository will not have everything. If something is missing, package it and send it back.
  • A bug report needs the command that was run, what happened, and the full output.
  • Things change between releases. When something is dropped, the commit says why.
  • Nothing here is sacred, not the documentation and not the code. If something is wrong, say so.
