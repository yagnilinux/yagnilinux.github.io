-> goals

“Man, your head is haunted; you have wheels in your head!” — Max Stirner, The Ego and Its Own

a goal that can be quoted to excuse a bad decision was written badly. these are meant to be hard to misuse.

  • users know what they are doing.
  • users take part. what is missing, they package and send back.
  • the whole system stays small enough for one person to read.
  • the base system boots the machine and installs packages. nothing else.
  • a script that can be read is preferred to a daemon that has to be trusted.
  • compatibility is dropped when keeping it means keeping complexity.

spooks

each of these is a fixed idea: something you were told a real system needs. requiem does without them.

a bootloader
the firmware starts the kernel.

an initramfs
the kernel mounts root itself.

systemd
busybox init and one boot script.

udev
busybox mdev.

shared libraries
everything is static.

NetworkManager
one file, read at every boot.

a package for every library
an application is one folder in ~/apps.

snap and flatpak
a tarball of files.

dbus
programs that talk without a message bus.

expectations

every user of requiem is expected to take part in it.

  • read the docs before asking.
  • read the script before reporting a bug in it.
  • package what is missing and send it back.
  • a bug report contains the command that was run and what it printed.
  • when someone helping you asks for something, give them that.
