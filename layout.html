-> layout

“Wealth consists not in having great possessions, but in having few wants.” — Epictetus

everything is static. with no loader, LD_PRELOAD and LD_LIBRARY_PATH do nothing, and glibc binaries do not run. build yours static, or package it.

there is no /lib because nothing is loaded at runtime, and no /sbin because root and users run the same programs.

apps

an application is one folder in ~/apps, the way it is on macos. as your own user, without root:

$ introit a netsurf     # ~/apps/netsurf
$ ls ~/apps/netsurf
bin  share  version

move the folder out and it is no longer installed: your shell only looks for programs in ~/apps/*/bin and /apps/*/bin. delete it and it is gone, with nothing left behind. introit u updates what is in ~/apps, and introit r netsurf is the same as rm -r ~/apps/netsurf. a new app shows up in a new shell.

installed as root, an app goes in /apps and every user gets it. if an app needs something from the base system that is missing, introit tells you what to run as root first.

command line tools are not apps. they stay in /bin. today the apps are netsurf and havoc.

the tree

/bin -> programs

/share -> data, fonts, firmware, kernel modules, python's library

/etc -> configuration

/boot -> the efi partition, holding the kernel

/var -> logs, and the package database in /var/db/introit

/home, /root -> users

~/apps, /apps -> applications, one folder each. yours, and everyone's

/mnt -> other filesystems

/dev, /proc, /sys, /run, /tmp -> made at boot

/usr -> a symlink to /, for #!/usr/bin/env

musl-dev puts headers and static libraries in /share/include and /share/lib. tcc links static by default.

mkrepo moves whatever a build puts in usr/bin, usr/sbin or sbin to /bin, and usr/share to /share. anything left in /usr or /lib fails the build.
