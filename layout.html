-> layout

there is one of everything here. every program is static, so there is no dynamic loader and no shared library anywhere on the system. LD_PRELOAD and LD_LIBRARY_PATH do nothing. glibc binaries do not run, so build yours static or cook a package for it.

no /lib, because there is nothing to load. no /sbin, because root runs what you run. /usr is a symlink to / for every old script that still says #!/usr/bin/env.

/bin -> programs

/share -> everything a program reads: data, fonts, firmware, kernel modules, python's library

/etc -> configuration

/boot -> the efi partition, holding the kernel

/var -> logs, and what cook knows in /var/db/cook

/home, /root -> users

/mnt -> whatever you mount

/dev, /proc, /sys, /run, /tmp -> made at boot

/usr -> a symlink to /

tcc's headers and static libraries land in /share/include and /share/lib with musl-dev, and tcc links static by default.

superlab holds every package to this. whatever a build drops in usr/bin, usr/sbin or sbin goes to /bin, usr/share goes to /share, and anything left in /usr or /lib does not leave the lab.
