who is requiem for?

people who want to understand every part of the system they run. try it in qemu first.

why is everything static?

a static program does not depend on anything installed beside it. it starts faster and behaves the same on every machine.

will a binary i downloaded run?

only if it is static. there is no loader, so LD_PRELOAD does nothing.

why is /usr a symlink?

the split between / and /usr came from a full disk in 1971. the symlink is kept for scripts that expect /usr/bin/env.

where is the bootloader?

there is none. the kernel is an efi program.

what replaces the usual parts?

systemd -> busybox init and one script

udev -> mdev

sudo -> doas

NetworkManager -> one wifi file

dbus, shared libraries, ld.so -> nothing

why is there no gnu software?

glibc resists static linking, and the gnu tools are larger than requiem needs. musl, busybox, oksh and bsd tools do the same work. everything is built with clang, lld and compiler-rt, so not even libgcc ends up inside a binary.

why not dérive?

dérive is good, and requiem learned a lot from it. but dérive is almost 100% gnu free. requiem is 100%. it ships built packages, so a base install takes seconds, apps live in ~/apps, the boot is 32 lines, and there is no bootloader.

but mostly:

“Do you really want to live in a world without Coca-Cola?” — Walter White

why is so little packaged?

packages are added when someone needs them. see packaging.

is it self-hosting?

not yet. the kernel needs gnu make, which requiem does not ship, so packages are built on another machine. tcc is for your own code.

are packages signed?

no. they are checked against sha256 sums in the index; the index itself is not signed.

does it run firefox?

not until someone ports it. netsurf works.

what hardware works?

x86-64 with uefi. it is tested in qemu; reports from real hardware are welcome.

license?

cddl 1.1. packages keep their own licenses.
