not answered here? read the documentation. still not answered? ask.

why is it called yagni/linux?

linux is only the kernel. jits, the boot script, the packages and the rest of the system are yagni. what you're referring to as linux is, in fact, yagni/linux. we're just being pedantic, like richard.

what does yagni mean?

you aren't gonna need it. it's from extreme programming: don't build something until you actually need it. we took it further than they meant.

is yagni for me?

probably not. read expectations. if that page annoyed you, that's your answer.

why is so little packaged?

because we can't maintain the world, and pretending otherwise is how distributions rot. the repository is a base to build on. you package what you need, and packaging is easy.

can you package something for me?

open an issue. better, package it yourself and open a pull request. packaging is easy, see for yourself.

why is everything static?

a static binary is one file. it doesn't need ld.so or matching library versions, and upgrading something else can't break it. docker exists because dynamic linking doesn't work. we just stopped doing the thing that doesn't work. you can copy it to another machine and it runs.

do you hate gnu?

yes. fuck gnu. here's why. free as in free of gnu.

why not alpine?

alpine does more. yagni does less, on purpose.

will x be added to base?

no. base is ours.

why is there bsd and apple code in it?

because it's good and it isn't gnu. doas and ksh come from openbsd, bc from freebsd, curses from netbsd. lzfse is apple's compression: packages unpack about four times faster than with gzip. bonjour is apple too, if you want name.local to work.

does it have an installer?

yes. yagni's calamares installer is here.

x11 or wayland?

wayland. xorg is a spook: millions of lines of code from 1987 that everyone serves because everyone always has. it was also the one package in yagni that couldn't be statically linked. it's gone. luwm is a wayland compositor, and the whole desktop is static. wayland.fyi makes the case better than we can.

does it run firefox?

no. firefox wants glibc and gtk. yagni has neither. netsurf is in the repository.

what hardware works?

x86-64 machines that boot with uefi. firmware for intel and realtek wifi is packaged, but nobody has tested it on a real card yet.

are packages signed?

no. the index has sha256 sums and jits checks every download against them, but nothing is signed. whoever controls the repository controls your packages, same as a git clone. running your own repository? SUMS=1 ./mkrepo does the same for yours.

is yagni self-hosting?

no. yagni can't build itself yet, and we won't pretend otherwise. the kernel only builds with gcc or clang, and its build system wants gnu make. we could be self-hosting tomorrow if we shipped gnu. we don't, at all. so for now the packages are built elsewhere, you get tcc for your own code, and self-hosting waits until it can be done without gnu.

what license is yagni under?

cddl 1.1, the license sun wrote for solaris. change one of our files and ship it, you share that file. link it with whatever you want, closed or open. the software it packages keeps its own license. bonus: the fsf says it's gpl-incompatible. we consider that a feature.

what font does the website use?

whatever your browser calls helvetica.
